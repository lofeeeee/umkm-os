P5-5 + P5-6 — Orchestrator, guardrail, tool registry (PRD.md §4.11, §6.6; AC-AIO-001/002/003, AC-AIC-004)
Tanggal: 2026-11-12

Artefak (crates/application/src/ai/, tanpa I/O; efek samping hanya lewat port)
- guardrails.rs: input — normalisasi (buang kontrol), kosong/ >2000 char → Block; frasa minta manusia & topik terlarang →
  Human; pola prompt injection (14) → suspicious. Output — canary per giliran, ≥40 char awal panduan toko, pola rahasia
  (sk-, api_key, bearer, password:, PEM) → Fail; topik terlarang → Human; kosong → Uncertain; dipotong 1500 char.
- tools.rs: 10 tool dengan skema JSON (additionalProperties false) + parse_args ketat (field asing ditolak, panjang,
  uuid, pola nomor pesanan, item unik ≤10, qty 1–99). authorize: nama tak dikenal → Unknown; tidak ditawarkan → Denied;
  ScopedRead/RestrictedWrite butuh pelanggan TERVERIFIKASI dari konteks percakapan (bukan argumen LLM → anti IDOR);
  handover selalu boleh bila aktif. Hasil ≤4000 byte; args_summary tanpa teks bebas pelanggan. Port ToolBackend per tenant.
- orchestrator.rs run_turn: Human Only → tanpa provider; guardrail input; retrieval (port Retriever, tenant-scoped);
  system prompt platform dengan aturan tetap + canary, panduan toko & konteks dibungkus pembatas sebagai DATA;
  tool ditawarkan = aktif ∩ capability, input mencurigakan → hanya Read + handover; loop tool ≤3 putaran (putaran akhir
  tanpa tool); fallback provider hanya untuk error sementara (bukan 401/400); usage dijumlah; output guardrail;
  keputusan via domain mode::decide (P5-9). TurnOutcome memuat status/error_code/tool records untuk metering (P5-8).
