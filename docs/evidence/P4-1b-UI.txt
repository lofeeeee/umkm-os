Artefak
- frontend/src/app/login/page.tsx  /auth/login 202 → langkah "Verifikasi dua langkah" (TOTP atau kode pemulihan;
  token tantangan hanya di memori; 401 = tantangan habis → kembali ke form password).
- frontend/src/app/security/page.tsx  halaman Keamanan: status, siapkan (kunci base32 dikelompokkan + tautan
  otpauth://), aktifkan → 10 kode pemulihan ditampilkan sekali, buat ulang kode, matikan (password + kode; tidak
  ditampilkan bila akun platform wajib MFA). Dengan ?tenant=: toggle "Wajibkan MFA untuk Owner, Manager, dan Admin"
  (tenant.update; ditolak bila sesi belum lolos MFA).
- frontend/src/dashboard/shell.tsx  tautan "Keamanan"; WithTenant mengarahkan ke /security?reason=mfa bila sesi
  wajib MFA (AUTH-011) atau toko menolak dengan reason=mfa_required (AUTH-012). Halaman beranda idem.
- frontend/src/lib/api.ts  tipe Session (mfa_verified, mfa_enrollment_required), MfaChallenge, isMfaRequired().
- frontend/e2e/mfa.spec.ts  TOTP dihitung di tes (node:crypto HMAC-SHA1) dari kunci yang tampil di layar.
- Tanpa dependency baru. QR code tidak ditampilkan (butuh library; kunci manual + tautan otpauth sudah didukung
  aplikasi authenticator umum) — dicatat sebagai tindak lanjut.

Cakupan mfa.spec.ts
- Toggle kebijakan toko sebelum sesi lolos MFA → pesan "Aktifkan MFA di akun Anda…", checkbox tetap off.
- Siapkan → kunci 32 karakter base32; kode salah → "Kode tidak valid"; kode benar → 10 kode pemulihan format
  xxxxx-xxxxx; status "Aktif · sisa kode pemulihan: 10".
- Sesi kini lolos MFA → kebijakan toko tersimpan dan tercentang.
- Keluar → masuk → langkah kedua dengan TOTP langkah berikutnya → "Toko saya"; halaman Pesanan dapat dibuka
  (Owner melewati kebijakan toko karena sesi lolos MFA).
- Masuk dengan kode pemulihan (huruf besar) → berhasil, sisa 9; kode yang sama dipakai lagi → "Kode tidak valid".
